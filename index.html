Why it works

Each task starts clean
A subagent gets only its brief, so leftovers from earlier tasks can't confuse it.
The main agent stays light
It keeps the plan and short reports, which leaves room to coordinate a long feature.
Reviewers judge independently
A reviewer reads the code and the spec. It doesn't see the implementer's reasoning or inherit its confidence.
Separate tasks can run together
Tasks that share no files and need nothing from each other can run in parallel.

What it costs

More total tokens
Every new subagent has to read the code again, and each review is another run.
It needs a good plan
A vague brief gets a vague result. Each task has to make sense to someone seeing the project for the first time.
Parallel writers can collide
Two agents editing the same file create conflicts, so those tasks should run one after the other.
Small jobs don't need it
For a one-file fix, dispatching agents takes longer than making the change.

The feature, file names and context figures are made up to show the idea. They aren't measurements, and the details vary between tools and teams.
